### 一、 需求文档 (PRD)

#### 1. 项目概述
本项目旨在搭建一个高性能、高安全性的个人技术博客与项目展示平台。系统采用前后端分离架构，前台注重极致的加载速度与 SEO，后台提供沉浸式的 Markdown 创作与站点结构管理体验。

#### 2. 用户角色
*   **访客**：浏览首页、项目、技术栈、待办等公开内容，触发 API 请求与静态资源加载。
*   **管理员（唯一）**：通过鉴权登录后台，进行文章编写、目录管理、资源上传及站点结构维护。

#### 3. 功能需求
**3.1 前台展示模块**
*   **导航系统**：一级目录渲染为顶部导航栏；鼠标悬停时，动态下拉展示该一级目录下的二级目录（固定页面无二级目录则不显示下拉）。
*   **固定页面**：
    *   **首页**：无二级目录。展示个人简历、获奖图片、参与项目、工作/实习经历。
    *   **项目页**：无二级目录。左侧为项目切换列表，右侧展示单项目详情（代码能力、解决方案、解决的问题），内容基于真实代码定制。
    *   **技术栈页**：无二级目录。展示所有 Tag 列表及对应文章数量，支持点击 Tag 筛选相关文章。
    *   **待办**：无二级目录。**其他**：作为容器目录，承接解散后的二级目录，允许包含二级目录。
*   **文章渲染**：解析 Markdown 格式，完美还原代码高亮、数学公式、图表等样式。

**3.2 后台管理模块**
*   **鉴权系统**：单用户登录，Token 校验，隐藏登录入口，拦截未授权访问。
*   **Markdown 编辑器**：提供网页端实时预览编写功能，支持快捷键、图片拖拽上传。
*   **目录与文件维护**：
    *   **解散逻辑**：
        *   解散一级目录：其下二级目录自动归入“其他”一级目录，文件保留在原二级目录。
        *   解散二级目录：其下文件自动归入“其他”一级目录下的“其他”二级目录。
    *   **拖拽管理**：支持树形结构拖拽，将二级目录（含文件）跨一级目录移动，或将文件跨二级目录移动。
*   **压缩包批量导入**：
    *   支持上传 ZIP 压缩包至指定二级目录。
    *   **安全校验**：后端解压后，校验根层级是否仅包含 `images` 文件夹和 `.md` 文件。若解压后仅有一个文件夹（重复压缩），则递归进入最深层单一文件夹直至符合要求或报错。
    *   **资源处理**：提取 `images` 中的图片上传至七牛云对象存储，并自动正则替换 `.md` 文件中的本地路径 `![](./images/xxx.jpg)` 为 CDN 绝对路径。

#### 4. 非功能需求
*   **性能**：1Mbps 带宽下保证 100 并发流畅（需动静分离，静态资源走 CDN）；页面动画 60fps 流畅。
*   **安全**：防 DDoS；Nginx 限制单 IP QPS > 10 时拉黑 1 分钟；七牛云防盗链；常规服务器安全加固。

### 二、 技术选型与架构设计

针对 **2核 2G 内存 1Mbps 带宽** 的严苛硬件限制，技术选型的核心原则是：**极致轻量、动静分离、内存保护**。

#### 1. 技术栈清单
*   **前端（前台）**：**Astro** + **Vue/React 岛屿架构**。Astro 默认零 JS 输出，首屏 HTML 极小，完美解决 1Mbps 带宽加载慢的问题；复杂交互（如导航下拉、动画）通过岛屿组件按需加载。
*   **前端（后台）**：**Vue 3** + **Vite** + **Pinia**。后台管理系统打包为独立 SPA，不影响前台性能。
*   **Markdown 编辑器**：**Vditor**。支持所见即所得、即时渲染（类似 Typora）和分屏预览，对中文语境优化极佳，自带图床上传接口。
*   **后端**：**Go (Gin 框架)**（已选定）。编译为单二进制文件，内存占用仅 20-30MB，并发性能极高，能最大程度把 2G 内存留给系统和缓存。
*   **数据库**：**SQLite**。单文件数据库，无需像 MySQL/PostgreSQL 那样常驻数百 MB 内存，对于单用户博客完全足够，配合 WAL 模式读写性能优异。默认使用纯 Go 驱动 `github.com/glebarez/sqlite`（底层 modernc.org/sqlite），**无需 CGO/GCC**；若压测发现写性能瓶颈，再评估 `mattn/go-sqlite3` 并引入 CGO 工具链。
*   **Web 服务器**：**Nginx**。仅用于 API 反向代理、HTTPS 卸载、限流与后台 SPA 托管；前台静态站不经过 ECS。
*   **对象存储**：**七牛云 Kodo**。静态站直传 Kodo 并由七牛 CDN 加速；文章图片同样存放于 Kodo。

#### 2. 核心难点解决方案
*   **1Mbps 带宽与 100 并发瓶颈**：
    *   1Mbps 带宽理论极限为 128KB/s。如果前台页面 JS/CSS 过大，100 人同时访问会瞬间打满带宽导致超时。
    *   **解法**：前台使用 Astro 进行 SSG（静态站点生成），构建产物**直传七牛云 Kodo 并由七牛 CDN 加速**，主域名解析到 CDN，不经过 ECS。ECS 的 1Mbps 带宽**仅用于提供 API、后台管理页面和构建时的取数请求**。API 返回的 JSON 数据通常只有几 KB，2核 CPU 和 Go 后端轻松支撑 100 并发 API 请求。
    *   **发布**：后台发布后由后端触发 GitHub Actions 重建静态站，构建成功后上传 Kodo 并刷新受影响 URL；构建失败时旧版本继续服务。新文章在重建完成前由 404 页临时从 API 渲染，仅作兜底。
*   **Markdown 图片路径替换**：
    *   开发时：使用 `![](./images/pic.jpg)`。
    *   上传/发布时：后端拦截该 Markdown 内容，使用正则 `!\[.*?\]\(\.?\/?images\/(.*?)\)` 匹配，将图片上传至七牛云，获取 URL 后替换为 `![alt](https://cdn.yourdomain.com/.../pic.jpg)`。
*   **压缩包递归校验**：
    *   后端使用 `archive/zip` (Go) 或 `adm-zip` (Node) 读取文件树。编写递归函数：若当前层级文件数 > 1 或包含非 `images`/`.md` 文件，则校验通过/失败；若当前层级只有一个文件夹，则指针下移，继续校验该子文件夹，直到触底。
*   **Nginx 限流与拉黑**：
    *   使用 `limit_req_zone` 限制 QPS。结合 Nginx Lua 模块（OpenResty）或简单的 `fail2ban` 监听 Nginx 429 错误日志，自动调用 `iptables` 或 `ufw` 封禁 IP 1 分钟。

### 三、 具体实施步骤

#### 阶段一：本地代码编译与开发
1.  **初始化项目**：
    *   前端：`npm create astro@latest` (前台)，`npm create vue@latest` (后台)。
    *   后端：`go mod init blog-api`，引入 Gin、GORM（`github.com/glebarez/sqlite` 纯 Go 驱动）、七牛云 SDK。
2.  **开发核心接口**：
    *   实现 JWT 鉴权中间件。
    *   实现目录树 CRUD 及“解散/拖拽”逻辑（SQLite 中使用 `parent_id` 维护树形结构）。
    *   实现压缩包上传、解压、递归校验、七牛云图片上传及 MD 内容替换接口。
3.  **前端联调**：
    *   集成 Vditor 编辑器，配置自定义上传接口，实现图片自动上传并插入 CDN 链接。
    *   实现树形拖拽组件（可使用 `vuedraggable` 或 `dnd-kit`）。

#### 阶段二：VM 虚拟机试运行 (Docker Compose)
为了避免环境污染并模拟服务器环境，在本地使用 Docker Compose 进行试运行。
1.  **编写 Dockerfile**：
    *   后端：使用多阶段构建（`golang:alpine` 编译，`alpine:latest` 运行），最终镜像约 20MB。SQLite 默认使用纯 Go 驱动，无需 CGO/gcc；若后续切换 `mattn/go-sqlite3`，构建阶段需安装 `gcc musl-dev`。
    *   前端：使用 `node:22-alpine` 构建，产物交由 `nginx:alpine` 托管（仅本地联调）。
2.  **编写 `docker-compose.yml`**：
    *   包含 `backend`、`frontend`、`nginx` 服务。
    *   映射 SQLite 数据库文件和数据卷到宿主机，确保数据持久化。
    *   **注意**：本地 compose 中的 nginx 托管 `frontend/dist` 仅用于联调；生产环境前台由七牛 Kodo + CDN 承载，ECS 上的 nginx 只服务 API 与后台 SPA。
3.  **本地测试**：
    *   在 VM 中运行 `docker compose up -d`。
    *   测试 100 并发 API 压测（使用 `wrk` 或 `jmeter`），观察内存是否溢出。
    *   测试压缩包上传与路径替换逻辑。

#### 阶段三：购买云服务器、域名与七牛云配置
1.  **阿里云 ECS 准备**：
    *   购买 2C2G ECS，操作系统选择 **Ubuntu 22.04 LTS** 或 **Debian 12**（比 CentOS 更省内存且软件源新）。
    *   **关键优化**：创建 2GB Swap 交换分区，防止极端情况下内存耗尽导致进程被 Kill。
        ```bash
        fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
        echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
        ```
2.  **七牛云对象存储配置**：
    *   创建两个公开读 Bucket：
        *   `blog-static`：托管 Astro 静态站。开启**静态网站托管**，首页文档 `index.html`，错误文档 `404.html`（用于新文章兜底）。
        *   `blog-assets`：存放文章图片。
    *   绑定自定义域名并配置 CNAME：
        *   `www.yourdomain.com` → `blog-static`，经七牛 CDN 加速。
        *   `cdn.yourdomain.com` → `blog-assets`，经七牛 CDN 加速。
    *   **缓存规则**：
        *   `/_astro/*`（文件名含哈希）：`Cache-Control: public, max-age=31536000, immutable`。
        *   HTML（`*.html` 与目录首页）：`max-age=300`；刷新负责即时生效，TTL 负责最终一致。
        *   `sitemap.xml`、`rss.xml`：`max-age=600`。
    *   **防盗链与 HTTPS**：`blog-assets` 开启 Referer 白名单（仅站点域名与 localhost）；两个域名均上传 SSL 证书并强制 HTTPS。注意七牛免费额度有限（约 10GB 存储 + 10GB CDN 回源/下载流量，以控制台为准），HTML 必须被 CDN 缓存，避免每次访问都回源 Kodo；HTTPS 请求可能单独计费，上线前确认账单项。
    *   **刷新配额**：文件刷新默认 500 URL/天（控制台单次 20，OpenAPI 单次 60），目录刷新约 10–11 次/天；发布后只刷新受影响 URL，详见 `doc/数据库与API设计.md` 第五节。
    *   创建用于 CI 的 AccessKey/SecretKey，存入 GitHub Secrets（`QINIU_AK`、`QINIU_SK`、`QINIU_STATIC_BUCKET`）。
3.  **域名与备案**：
    *   购买域名，完成 ICP 备案（国内服务器必须，主域名与各子域均需覆盖）。
    *   阿里云解析：
        *   `www` CNAME 到七牛 CDN 提供的加速域名（静态站）。
        *   `cdn` CNAME 到七牛 CDN（图片资源）。
        *   `api` A 记录指向 ECS IP（Go API）。
        *   `admin` A 记录指向 ECS IP（后台 SPA）。
    *   `www`/`cdn` 的证书在七牛 CDN 控制台上传；`api`/`admin` 在 ECS 上用 certbot 申请。

#### 阶段四：CI/CD 流水线配置 (GitHub Actions)
在 GitHub 仓库创建 `.github/workflows/deploy.yml`。前台走 Kodo 直传，后端与后台 SPA 走 ECS；内容发布事件通过 `repository_dispatch` 触发，只重建前台并刷新受影响 URL。

```yaml
name: Deploy Blog

on:
  push:
    branches: [main]
  repository_dispatch:
    types: [content-published]

concurrency:
  group: deploy-blog
  cancel-in-progress: true

jobs:
  frontend:
    runs-on: ubuntu-latest
    env:
      SITE_URL: https://www.yourdomain.com
      QINIU_AK: ${{ secrets.QINIU_AK }}
      QINIU_SK: ${{ secrets.QINIU_SK }}
      QINIU_STATIC_BUCKET: ${{ secrets.QINIU_STATIC_BUCKET }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }

      - name: Build Frontend
        env:
          PUBLIC_API_BASE_URL: ${{ secrets.API_BASE_URL }}
        run: |
          cd frontend
          npm install
          npm run build

      - name: Install qshell
        run: |
          curl -fsSL -o qshell.tar.gz \
            https://github.com/qiniu/qshell/releases/download/v2.20.1/qshell-v2.20.1-linux-amd64.tar.gz
          tar -xzf qshell.tar.gz
          sudo mv qshell /usr/local/bin/
          qshell account "$QINIU_AK" "$QINIU_SK"

      # 先传带哈希的静态资源；再传 HTML。qupload2 不会删除远端文件，旧资源得以保留
      - name: Upload hashed assets
        run: |
          qshell qupload2 --src-dir=frontend/dist/_astro \
            --bucket="$QINIU_STATIC_BUCKET" --key-prefix=_astro/ --overwrite

      - name: Upload HTML and metadata
        run: |
          qshell qupload2 --src-dir=frontend/dist \
            --bucket="$QINIU_STATIC_BUCKET" --overwrite --skip-path-prefixes=_astro/

      - name: Refresh CDN
        continue-on-error: true   # 刷新失败不阻塞发布，HTML 短 TTL 会自愈
        run: |
          if [ "${{ github.event_name }}" = "repository_dispatch" ]; then
            echo '${{ toJSON(github.event.client_payload.urls) }}' | jq -r '.[]?' > urls.txt
          else
            find frontend/dist -name '*.html' \
              | sed 's#^frontend/dist##; s#index.html$##' \
              | sed "s#^#$SITE_URL#" > urls.txt
            echo "$SITE_URL/sitemap.xml" >> urls.txt
            echo "$SITE_URL/rss.xml" >> urls.txt
          fi
          # 单日配额 500；优先保留后端传入的顺序（文章页 > 列表/首页 > 其它）
          head -n 500 urls.txt > urls.limited.txt
          if [ -s urls.limited.txt ]; then
            qshell cdnrefresh -i urls.limited.txt
          fi

  backend:
    if: github.event_name == 'push'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: 'stable' }
      - name: Build Backend
        run: |
          cd backend
          CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o blog-api .
      - name: Deploy Backend to ECS
        uses: easingthemes/ssh-deploy@v5.0.3
        env:
          SSH_PRIVATE_KEY: ${{ secrets.ECS_SSH_KEY }}
          REMOTE_HOST: ${{ secrets.ECS_IP }}
          REMOTE_USER: root
          SOURCE: "./backend/blog-api ./deploy/nginx.conf"
          TARGET: "/opt/blog/"
          ARGS: "-avzr"
      - name: Restart Backend
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.ECS_IP }}
          username: root
          key: ${{ secrets.ECS_SSH_KEY }}
          script: |
            install -m 644 /opt/blog/nginx.conf /etc/nginx/conf.d/blog.conf
            nginx -t && systemctl reload nginx
            systemctl restart blog-api

  admin:
    if: github.event_name == 'push'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - name: Build Admin
        env:
          VITE_API_BASE_URL: ""   # 生产同源，经 admin 子域 Nginx 反代 /api/

        run: |
          cd admin
          npm install
          npm run build
      - name: Deploy Admin SPA to ECS
        uses: easingthemes/ssh-deploy@v5.0.3
        env:
          SSH_PRIVATE_KEY: ${{ secrets.ECS_SSH_KEY }}
          REMOTE_HOST: ${{ secrets.ECS_IP }}
          REMOTE_USER: root
          SOURCE: "./admin/dist/"
          TARGET: "/opt/blog/admin/"
          ARGS: "-avzr --delete"
```

**说明**：
*   前端构建需要读取公开 API，`API_BASE_URL` 指向 `https://api.yourdomain.com`。
*   后端发布文章后，用最小权限 GitHub PAT 调用 `repository_dispatch`，`client_payload.urls` 传入**已去重、按优先级排序的完整 URL 列表**（文章页 > 列表/首页 > tag > sitemap/rss），Actions 直接写入刷新列表。
*   `concurrency` 会取消进行中的旧构建。由于静态资源先传、HTML 后传且不删旧资源，即使中途取消，旧 HTML 仍能引用旧资源，页面保持可用。
*   构建或上传失败时不要执行刷新步骤；工作流失败即中止，旧站继续服务。回滚 = 重新部署上一个 commit 的构建产物。

#### 阶段五：安全加固与 Nginx 限流配置
在 ECS 上配置 Nginx，仅服务 `api.` 与 `admin.` 子域；主站 `www.` 由七牛 CDN + Kodo 承载，不经过 ECS。

```nginx
# /etc/nginx/conf.d/blog.conf
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

server {
    listen 80;
    server_name api.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    location /api/ {
        limit_req zone=api_limit burst=20 nodelay;
        limit_req_status 429;

        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

server {
    listen 80;
    server_name admin.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name admin.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/admin.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.yourdomain.com/privkey.pem;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    root /opt/blog/admin;
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后台 SPA 与 API 同源，避免跨域与 Cookie 的 SameSite 问题
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

**主站 HTTPS 与缓存**：`www` 的证书、HTTP→HTTPS 跳转、缓存规则都在七牛 CDN 控制台配置；ECS 不参与主站静态流量。

**CORS**：公开读接口由 Go 中间件仅对 `https://www.yourdomain.com` 放行（供 404 兜底页调用）；后台管理接口不开放 CORS——后台 SPA 由 `admin` 子域 Nginx 同时反代 `/api/`，与 API 同源，避免 Cookie 的 SameSite 问题。不要把 CORS 写成 Nginx 的全局头。

**服务托管**：Go 服务用 systemd 托管（`/etc/systemd/system/blog-api.service`，`Restart=always`，工作目录 `/opt/blog`），CI 中的 `systemctl restart blog-api` 依赖该 unit。

**防 DDoS 与 IP 拉黑脚本 (结合 Fail2ban)**：
1. 安装 `fail2ban`。
2. 配置 `/etc/fail2ban/filter.d/nginx-limit-req.conf`，匹配 Nginx 的 429 错误日志。
3. 配置 `/etc/fail2ban/jail.local`，设置 `bantime = 60` (拉黑1分钟)，`findtime = 60`，`maxretry = 5`。
4. 这样当某个 IP 频繁触发 Nginx 限流，Fail2ban 会自动将其加入 iptables 黑名单，彻底阻断其连接，保护服务器资源。

#### 阶段六：上线与监控
1.  **数据初始化**：在后台创建固定的“首页、项目、技术栈、待办、其他”一级目录。
2.  **监控**：在 ECS 上安装 `htop` 和 `vnstat`（监控带宽流量）。由于内存仅 2G，建议关闭不必要的系统服务（如 `unattended-upgrades` 等）。
3.  **七牛云额度监控**：在七牛云控制台设置“费用预警”，当 10GB 免费额度即将耗尽时发送短信/邮件通知，防止意外产生高额账单。
4.  **发布验证**：每次发布后检查 Actions 构建结果、Kodo 上传记录与 CDN 刷新结果；构建失败时确认旧站仍可访问且未触发刷新。
5.  **刷新配额监控**：记录刷新 API 返回的 `urlSurplusDay` / `dirSurplusDay`；接近上限时优先保证文章页刷新，其余依赖 HTML 的 5 分钟 TTL 自愈。
